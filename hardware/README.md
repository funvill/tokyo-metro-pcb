## Regenerating the schematic

```
cd ../tools
python -X utf8 make_schematic.py ../hardware/tokyo-metro-pcb.kicad_sch 248
```

`tokyo-metro-pcb.kicad_sch.template` is a **required input**: a pristine copy
of the Montréal sheet, committed alongside the schematic. The generator always
builds from it, never from its own last output - reading its own output moved
the generated power symbols outside the drop region and left 130 duplicate
uuids on the second run.

It rebuilds the whole LED section — symbols, rails, row decoupling caps,
chain wiring and the `CHAIN1`…`CHAIN12` row labels — and leaves the
controller block and the test-point column untouched. It is safe to re-run:
the second run drops what the first generated and produces the same bytes.

Three things it has to get right, each of which it got wrong first:

- **Keep the controller's wiring.** Dropping every wire on the sheet leaves
  U1, R1 and the test points floating, with nothing on `LED_IN` or
  `LED_OUT`. Only wires below `GRID_TOP` *and* right of `GRID_LEFT` belong
  to the grid; the test-point column runs down to y = 83 at x = 24.
- **Do not reuse Montréal's row label names.** Its last output was tied to
  the `LED_OUT` test point with a second label, `ROW8`. With 13 rows that
  collides, shorting LED160 to the chain output. Generated labels are
  `CHAIN*`, and stray `ROW*` labels are dropped.
- **Re-uuid every uuid in a cloned block**, not just the first. A symbol
  carries one per property, so cloning 248 LEDs left four uuids shared
  across all of them.

## Checking the schematic for overlaps

```
python -X utf8 ../tools/check_schematic.py tokyo-metro-pcb.kicad_sch -v
```

A generated sheet can be electrically perfect and unreadable: nothing in the
netlist notices a decoupling capacitor sitting on a global label, and KiCad's
ERC does not check it either. The checker takes each symbol's outline from
its `lib_symbols` definition, rotates and moves it to the instance, and adds
a box for every global label and every *visible* Reference and Value - the
hidden ones are metadata and counting them buries the real collisions in 900
false ones. It reports 710 placed items and 0 overlapping pairs.

Three overlaps it found, all now fixed in the generator:

- the row capacitors sat on their own row's input label (`x_cap = ox - 30.48`
  moves them clear), and then on the mounting-hole column (grid origin moved
  to `95,70`);
- Montréal's `LED_DATA` and `LED_IN` labels sat directly on R1's body,
  because they were placed on its pins with no wire at all - each now gets a
  5.08 mm stub wire;
- C1's Value text is 16 mm wide and the gap between U1 and the +5V symbol is
  14.5 mm, so it is moved to the clear band below the controller.

## The label font

The board draws its station names in **Archivo Narrow SemiBold**, set as
`(face ...)` on every `gr_text`. That is not cosmetic: every label
placement, capsule and collision check in the pipeline is computed from
this face, and KiCad's default stroke font is 35-59% wider. Drawn in the
stroke font the names are wider than the space cleared for them; drawn in
Verdana, which is what KiCad substitutes when the face is missing, wider
still.

The font is **embedded in the board** (`embedded_fonts yes`, with the TTF
in the `embedded_files` section - it is most of the file's 7 MB), so the
board carries it and does not depend on what any particular machine has
installed. Embedding is done by `board.EmbedFonts()` through pcbnew, and
it only works once the board-level `embedded_fonts` flag is set AND the
font resolves on the machine doing the embedding - with the flag off, or
the font missing, it runs and silently embeds nothing.

If the face ever has to be re-embedded, install `fonts/ArchivoNarrow-SemiBold.ttf`
and run:

```
"C:/Program Files/KiCad/10.0/bin/python.exe" -c "import pcbnew; b=pcbnew.LoadBoard('tokyo-metro-pcb.kicad_pcb'); b.EmbedFonts(); pcbnew.SaveBoard('tokyo-metro-pcb.kicad_pcb', b)"
```

Check it took: `kicad-cli pcb render` prints a substitution warning when
the face is missing, and says nothing when it is found.
